# Оплата заказов через СБП ЮKassa

Магазин 1515932. Интеграция интернет-оплаты через redirect API.
Покупатель получает ссылку на согласованный заказ с уже указанной суммой.
Сайт открывает страницу ЮKassa с QR на компьютере или выбором банка на телефоне.
Одновременно могут оплачиваться разные заказы.

На главной странице в блоке онлайн-консультаций есть кнопка оплаты согласованной
консультации за 500 рублей. Она вызывает `POST /api/yookassa/consultation`.
Цена и назначение берутся с сервера. Повторный запрос в течение 30 минут
использует тот же подписанный счёт из HttpOnly-cookie, чтобы повторное нажатие
не создавало ещё один платёж. Покупатель не вводит сумму.
Перед следующей отдельной консультацией требуется новый счёт. После окончания
срока действия прежнего счёта кнопка автоматически выдаёт новый.

## Настройка сервера

- `YOOKASSA_SHOP_ID=1515932`
- `YOOKASSA_SECRET_KEY` — действующий ключ из кабинета ЮKassa
- `PAYMENT_ADMIN_TOKEN` — отдельный случайный токен минимум 32 байта для внутренней системы заказов
- `PAYMENT_SIGNING_SECRET` — отдельный случайный секрет минимум 32 байта для подписи счетов и cookies
- `PAYMENT_SITE_URL=https://web.curvedlines.ru`

Хранить значения в защищённых переменных среды сервера. Не коммитить секреты.
Проверить фактический production-хостинг перед публикацией. В репозитории есть
инструкции и для Vercel, и для standalone на Windows, состояние Vercel пока недоступно.
Не задавать `YOOKASSA_ALLOW_TEST=true` для действующего магазина.

## Выставление согласованного заказа

Защищённый `POST /api/yookassa/invoices` вызывается внутренней системой заказов
после согласования услуги и цены. Заголовок `Authorization: Bearer <PAYMENT_ADMIN_TOKEN>`.
Никакие секреты не передаются покупателю. Пример JSON:

```json
{"orderId":"consult-20261110-001","amount":"920.00","description":"Онлайн-консультация"}
```

Суммы от 500 до 700 000 рублей. Ответ содержит `paymentUrl`, точную сумму и
срок действия (30 минут). Эта ссылка передаётся покупателю. На странице оплаты
нет поля изменения суммы. При переходе к оплате цена проверяется по серверной подписи.
Номер заказа должен быть уникальным и назначаться системой заказов, а не покупателем.
Сумму и описание существующего заказа менять нельзя — нужен новый номер.

Ключ идемпотентности привязан к номеру заказа. Он защищает от повторного создания
платежа в течение срока хранения ключа ЮKassa (24 часа). Перед повторной выдачей
ссылки по старому заказу оператор обязан проверить его статус в ЮKassa. После
истечения 24 часов не переиспользовать старый номер заказа автоматически.
Для массового автоматического перевыставления потребуется постоянный реестр заказов.

## Статусы

В ЮKassa настроить URL `https://web.curvedlines.ru/api/yookassa/webhook`, события
`payment.succeeded`, `payment.canceled`. Обработчик повторно получает платёж через
API, проверяет магазин, сумму, метаданные и статус. Данные из тела уведомления
сами по себе не подтверждают оплату. Повторная доставка безопасна.

После возврата из банка `/pay/result` проверяет статус через API. Для связи с
платежом используется подписанная HttpOnly Secure SameSite=Lax cookie. У разных
заказов разные cookies. При смене браузера статус уточняется у исполнителя.

Защищённый `GET /api/yookassa/payment-status?paymentId=<id>` возвращает проверенный
статус для внутренней системы. Действующий реестр платежей — кабинет ЮKassa.
Для платежей `source=p2pobmen` webhook также подтверждает получение оплаты
в сделке — см. [настройку p2pobmen](./p2pobmen-payments.md).
Автоматическая выдача товара, подтверждение записи, MAX/email и налоговые чеки
для обычных заказов этой версией не выполняются. Фискализацию необходимо отдельно согласовать с
настройками магазина, она не считается подключённой по факту приёма платежа.

## Проверка и запуск

`node --test tests/yookassa.test.mjs`, `npx tsc --noEmit`, `npm run build`.
Прежде чем включать оплату, проверить ключ и параметры магазина, настроить
уведомления, развернуть код и привязать внутреннюю систему заказов к `/invoices`.
Первую реальную оплату выполняет владелец. Проверить `succeeded`, сумму, номер
заказа, отображение возврата, а также повторное нажатие и отмену.
