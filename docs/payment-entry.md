# Постоянная страница оплаты /pay

Постоянный QR содержит `https://web.curvedlines.ru/pay`. Эта же ссылка сохранена
в реквизитах лота. При одной принятой неоплаченной сделке продавца страница
сразу перенаправляет на **уже созданный** платёж ЮKassa: выбор банка с готовой
суммой, без формы ввода ID и без дополнительной кнопки на нашем сайте.
Страница не создаёт платежи, не принимает
сделки, не отправляет сообщения и не подтверждает получение денег.
Существующие обработчики и их конфигурация не изменены.

Общая ссылка работает при **ровно одной** принятой неоплаченной сделке
одновременно — это согласованное ограничение схемы. Для проверки запрашиваются
две сделки в состояниях ACCEPTED/PAID. Если найдено несколько, страница
блокирует общий переход и предлагает персональную ссылку из чата. Она никогда
не выбирает последнюю, самую дорогую или первую из нескольких сделок.
Если платёж ещё готовится, браузер последовательно проверяет готовность
до 90 секунд; запросы не накладываются. Затем можно повторить проверку кнопкой.
Логика выбора вынесена в read-only `GET /api/pay/active`.
Персональная ссылка `/pay?ref=<UUID-заявки>` сразу открывает нужный платёж.
Короткие последовательные номера не поддерживаются: они позволяют перебирать
чужие заявки. Список заявок публично не выдаётся.

Перед редиректом сервер повторно читает собственную заявку продавца и сверяет её сумму, RUB, состояние,
номер, чат и метаданные с существующим платежом этого магазина. При поиске
по UUID просматриваются максимум три страницы по 100 платежей за последние
7 дней. Если весь диапазон не просмотрен, данных недостаточно или платежей
несколько, переход к оплате блокируется; нужно использовать персональную
ссылку из чата. Цена из query-параметров никогда не принимается.

Закрытые заявки, полученная оплата, истёкшие и отменённые платежи не предлагают
повторную оплату. Если платёж ещё не создан существующей системой, страница
предлагает дождаться ссылки. Рабочую автоматику, расписания и секреты этот
интерфейс не включает и не перенастраивает.

Новые переменные среды не требуются. Используются существующие настройки
магазина и подтверждённой сессии продавца. Значения не попадают в браузер.
Страница не индексируется через существующий layout `/pay`, все внешние
запросы используют `no-store`. Проверять с реальными сервисами только
чтение; для тестов внешние ответы заменяются заглушками.
