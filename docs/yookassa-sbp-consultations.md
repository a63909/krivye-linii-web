# ЮKassa: постоянный QR СБП с изменяемой суммой

Интеграция использует платежную табличку ЮKassa и кассовую ссылку (`pos_link`).
Картинка QR не меняется: перед каждой оплатой сервер записывает в одну и ту же
кассовую ссылку сумму текущей консультации. Покупатель сканирует постоянный QR и
видит уже указанную сумму.

Это отдельный офлайн-сценарий ЮKassa. Обычная интернет-оплата с
`confirmation.type=redirect` и уникальной `confirmation_url` здесь не используется.

## Что необходимо получить у ЮKassa

1. Подключенный настоящий магазин для офлайн-платежей по платежным табличкам.
2. Физическую платежную табличку с постоянным QR-кодом.
3. Идентификатор торговой точки (`gateway_id`).
4. Секретный ключ магазина.
5. После активации таблички — идентификатор кассовой ссылки `pos_link.id`.

Функциональность платежных табличек недоступна в тестовом магазине. Подключение
и первый тест выполняются на настоящем магазине по инструкции ЮKassa.

## Активация постоянного QR

После получения таблички отсканируйте ее QR. Полученную ссылку вида
`https://qr.nspk.ru/...` активируйте один раз:

```http
POST https://api.yookassa.ru/v3/pos_links
Authorization: Basic <shopId:secretKey>
Idempotence-Key: <уникальный ключ>
Content-Type: application/json

{
  "recipient": {
    "gateway_id": "<идентификатор торговой точки>"
  },
  "pos_link_data": {
    "link": "https://qr.nspk.ru/<код с таблички>"
  }
}
```

В ответе сохраните значение `id` вида
`pl-1da5c87d-0984-50e8-a7f3-8de646dd9ec9`. Это `YOOKASSA_POS_LINK_ID`.
Сам QR с таблички остается постоянным — именно его можно загрузить на площадку.

## Переменные окружения

```env
YOOKASSA_SHOP_ID=1515932
YOOKASSA_SECRET_KEY=
YOOKASSA_POS_LINK_ID=pl-...
CONSULTATION_PAYMENT_API_TOKEN=
CONSULTATION_PAYMENT_STATUS_URL=
CONSULTATION_PAYMENT_STATUS_TOKEN=
```

Секретный ключ и служебные токены хранятся только на сервере. Их нельзя
добавлять в клиентский код, переписку или Git.

## Запись суммы перед оплатой

Когда стоимость реальной консультации согласована и покупатель готов платить,
внутренний агент вызывает защищенный серверный метод:

```http
POST /api/yookassa/consultation-payment
Authorization: Bearer <CONSULTATION_PAYMENT_API_TOKEN>
Content-Type: application/json

{
  "consultationId": "consult-2026-000123",
  "amount": "920.00"
}
```

Сервер проверяет, что постоянный QR активен и не занят другим ожидающим
платежом, затем создает платеж с:

- точной суммой из подтвержденной заявки;
- `pos_link.id` из серверной конфигурации;
- `confirmation.type = external`;
- сроком оплаты 10 минут;
- автоматическим подтверждением платежа (`capture = true`).

Ответ:

```json
{
  "ok": true,
  "consultationId": "consult-2026-000123",
  "amount": "920.00",
  "paymentId": "...",
  "status": "pending",
  "paymentMode": "permanent_pos_link",
  "qrCodeChanged": false,
  "reused": false,
  "expiresAt": "2026-11-02T18:30:00.000Z"
}
```

После этого покупатель сканирует ранее загруженный постоянный QR. Новый QR и
новая ссылка покупателю не отправляются.

Повтор того же запроса с теми же `consultationId` и суммой безопасен: сервер
вернет уже созданный платеж с `reused: true` и не перезапишет QR второй раз.
У такого повторного ответа `expiresAt` равен `null`, потому что ЮKassa не
возвращает исходный срок действия при чтении уже созданного платежа.

## Защита от пересечения платежей

Одна кассовая ссылка одновременно содержит только одну сумму. Поэтому API не
записывает новую сумму, пока предыдущий платеж по этому QR имеет статус
`pending`. В таком случае сервер отвечает `409`:

```json
{
  "ok": false,
  "error": "По постоянному QR уже ожидается другой платёж",
  "activePaymentId": "..."
}
```

Новая заявка может активировать QR после успешной оплаты, отмены или истечения
предыдущего платежа. Для одновременных оплат нужны несколько отдельных
платежных табличек и несколько `pos_link.id`.

## HTTP-уведомления

В кабинете ЮKassa укажите:

```text
https://web.curvedlines.ru/api/yookassa/webhook
```

События: `payment.succeeded` и `payment.canceled`.

Обработчик повторно получает платеж через API ЮKassa и только после проверки
передает статус внутреннему агенту. Если задан
`CONSULTATION_PAYMENT_STATUS_URL`, туда отправляются идентификатор консультации,
платежа, сумма и подтвержденный статус.

## Порядок запуска

1. Попросить менеджера ЮKassa подключить офлайн-платежи по платежным табличкам.
2. Получить табличку, `gateway_id` и секретный ключ.
3. Активировать QR и сохранить выданный `pos_link.id`.
4. Добавить серверные переменные окружения.
5. Настроить уведомления `payment.succeeded` и `payment.canceled`.
6. Записать минимальную сумму, отсканировать постоянный QR и провести реальный
   тестовый платеж.
7. Загрузить изображение этого же постоянного QR на площадку.
